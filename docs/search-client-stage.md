# Клиентский поиск: результат этапа

## Контракт текущего шага

На `/search/` заранее выведены все 12 статей через существующий `ArticleCard`. JavaScript фильтрует эти же DOM-элементы по заголовку, именам авторов и `keywords`, не по аннотации. Отдельного загружаемого индекса нет.

Пустой запрос, запрос из пробелов и «Сбросить поиск» показывают все статьи. Это явное уточнение прежнего контракта в `page-map.md`, где пустому запросу соответствовала только подсказка. Поиск нечувствителен к регистру и ё/е, все слова запроса должны присутствовать в объединённых поисковых полях карточки. Порядок исходного списка сохраняется.

## Файлы

- `src/components/SearchForm.astro`: label «Поиск по статьям», кнопки «Найти» и «Сбросить поиск», существующие токены и фокус. До запуска скрипта кнопки отключены, чтобы форма не отправлялась без JavaScript.
- `src/pages/search.astro`: исходный список `ArticleCard`, keywords в `data-search-keywords` его элементов, состояния `all`/`found`/`empty`, доступное уведомление с количеством результатов, пустое состояние и `noscript`.
- `src/scripts/article-search.ts`: локальный DOM-индекс, фильтрация через `hidden`, безопасный текст через `textContent`, `URLSearchParams`, `history.pushState`, восстановление из URL на старте, `popstate` и `pageshow`. Карточки не пересоздаются; повторный одинаковый запрос не добавляет запись истории.
- `src/components/SiteHeader.astro`, `src/pages/404.astro`: убраны устаревшие сообщения о неподключённом поиске.
- `docs/search-stage.md`: ссылка из отчёта о статичной рамке на текущий этап.

Backend, API, `fetch`, `XMLHttpRequest`, `innerHTML`, внешние поисковые сервисы и новые зависимости не добавлены. Данные статей, `ArticleCard`, layouts и дизайн-токены не менялись.

## Проверенные сценарии

Chromium / Playwright, production preview, на обеих ширинах 390 и 1440 CSS-пикселей:

| Сценарий | Результат |
| --- | --- |
| Открыть `/search/` | Состояние `all`, все 12 статей |
| Нажать «Найти» с `открытая наука` | Состояние `found`, 2 статьи: `open-science-review` и `keywords-in-context`; второе совпадение найдено через keywords |
| Enter с `неттакойпубликации12345` | Состояние `empty`, 0 карточек, запрос показан текстом, доступны пояснение и сброс |
| «Сбросить поиск» | Поле пустое, `q` удалён из URL, все 12 карточек, фокус в поле |
| Back/Forward: все → найденные → пустые → сброс | Поле, URL и выдача восстановлены на каждом из шести переходов назад/вперёд |
| Прямой URL `?q=открытая наука` и перезагрузка | Поле и 2 результата восстановлены |
| Прямой URL с отсутствующим запросом и перезагрузка | Поле и пустая выдача восстановлены |
| Пустой запрос и пробелы | Все 12 статей |
| `  ОТКРЫТАЯ    НАУКА  ` | Те же 2 результата, внешние пробелы удалены |
| `Елена Мирова` | 5 статей по имени автора |
| `ВЁРБИНА` | 7 статей, подтверждено сравнение ё/е и регистра |
| `соавторство` | 1 статья по keywords: `long-material-description` |
| `мирова соавторство` | Та же статья: все слова могут находиться в разных разрешённых полях |
| `доказательств`, присутствующее только в аннотациях | 0 результатов: аннотации исключены из индекса |
| Запрос с HTML и обработчиком события | Выведен буквально, DOM-изображение не создано, код не исполнился |
| Повторить тот же запрос | Лишняя запись истории не создана |
| Дополнительный параметр `ref=course` и hash | Сохранены при поиске и сбросе; меняется только `q` |
| Открыть обе найденные статьи и вернуться Back | HTTP 200, восстановлены URL, подтверждённый запрос и 2 карточки, а не несохранённый черновик поля |
| Запрос из 3000 символов и текст 200% | Нет горизонтального переполнения документа |
| Клавиатура | Skip-link работает, поле и «Найти» доступны по Tab, видимый контур 3 px |

Без JavaScript проверены обе ширины и три URL: без `q`, с совпадающим и с отсутствующим запросом. Во всех случаях видны исходные 12 карточек и `noscript`; формы не отправляются по Enter, ссылка в статью работает. Параметр `q` без JavaScript намеренно не применяется.

Во время фильтрации, сброса и переходов истории нет запросов типов fetch/XHR/document. Chromium повторно запрашивает локальный favicon при изменениях истории — это не запрос поисковых данных. Идентичность всех 12 DOM-узлов карточек сохранена. Необработанных JavaScript-ошибок в основных сценариях не обнаружено.

## Ограничения

Поиск работает по подстрокам всех введённых слов, без морфологии, исправления опечаток и ранжирования. Все карточки включены в исходный HTML; проверки производительности на больших наборах не проводились. Браузерные проверки выполнены в Chromium, не на физических устройствах и не во всех браузерах. Полная проверка со скринридером не проводилась. Публикация не выполнялась.
