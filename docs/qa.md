## Console и сеть

Счётчики ниже относятся к отдельным инструментированным прогонам. HTTP 304 — успешная повторная проверка кэша, не ошибка.

| Прогон | Запросы / ответы | HTTP 200 / 304 | Неуспешные запросы | Console / pageerror |
| --- | --- | --- | --- | --- |
| 12 комбинаций страниц и viewport | 98 / 98 | 33 / 65 | 0 | 0 / 0 |
| Меню, маршрут и архив | 246 / 245 | 80 / 165 | 1: favicon, `net::ERR_ABORTED` | 0 / 0 |
| Поиск, история, прямые URL и reload | 88 / 88 | 43 / 45 | 0 | 0 / 0 |

Типы запросов:

| Прогон | document | stylesheet | font | image | other |
| --- | --- | --- | --- | --- | --- |
| Матрица страниц | 12 | 16 | 48 | 10 | 12 |
| Меню и маршрут | 30 | 32 | 120 | 32 | 32 |
| Поиск | 10 | 10 | 40 | 0 | 28 |

- Во всех трёх прогонах: нет HTTP-ответов 4xx/5xx, внешних запросов, fetch или XHR; не зафиксировано сообщений console и необработанных ошибок страницы.
- При навигации один запрос `/favicon.svg` отменён с `net::ERR_ABORTED`, поэтому в прогоне меню запросов на один больше, чем ответов. Это наблюдение сохранено, а не исключено из статистики.
- Контрольная прямая загрузка `/favicon.svg`: HTTP 200, `content-type: image/svg+xml`, тело содержит SVG. Повторный стабильный переход главная → архив не дал неуспешных запросов. Оснований считать favicon отсутствующим нет.
- Фильтрация, сброс и переходы истории не вызвали запросов document/fetch/XHR. Во время этих взаимодействий Chromium сделал 18 локальных запросов favicon; это не загрузка поисковых данных.
- Дополнительный прогон без JavaScript не включён в счётчики трёх основных прогонов; в нём проверены отсутствие сообщений console/pageerror и HTTP 200 документов.

## Подтверждённые проблемы и ограничения функций

Описания ниже фиксируют состояние на момент обнаружения. После согласования исправлены только QA-01 и QA-02; QA-03 и QA-04 не менялись. Номера строк относятся к исходной ревизии `4661247`.

### QA-01 — недоступный «Архив» в крошках статьи

- Текущий статус: **FIXED / RETEST PASS**.
- Приоритет: средний.
- Источник: `src/layouts/ArticleLayout.astro:25`.
- Воспроизведение: открыть выбранную статью на 390 или 1440 px, проверить хлебные крошки.
- Факт: «Архив» выведен как недоступный элемент, без ссылки, хотя `/archive/` работает и возвращает HTTP 200.
- Ожидание: переход к существующему архиву из крошек. Сейчас он доступен через главное меню или через выпуск, но не через этот элемент крошек.

### QA-02 — ложная подпись о готовящемся выпуске

- Текущий статус: **FIXED / RETEST PASS**.
- Приоритет: средний.
- Источник: `src/layouts/ArticleLayout.astro:87`; привязка описания ссылки — строка 85.
- Воспроизведение: прокрутить статью к ссылке «К выпуску 2026, № 1», затем перейти по ней.
- Факт: рядом показано «Страница выпуска готовится. Ссылка сохранена для следующего этапа.», но ссылка успешно открывает существующий выпуск с HTTP 200.
- Текст также привязан к ссылке через `aria-describedby`; его фактическое озвучивание скринридером в этом QA не проверялось.
- Ожидание: подпись соответствует уже доступной странице выпуска.

### QA-03 — родительский раздел не обозначен в меню

- Приоритет: низкий; ограничение навигационной индикации, не сломанная ссылка.
- Источник: `src/components/SiteHeader.astro:18`.
- Факт: на страницах выпуска и статьи нет активного пункта главного меню, поскольку сравнение URL точное. На самом `/archive/` пункт «Архив» обозначен корректно.
- Для обозначения родительского раздела нужно отдельно согласовать поведение; дочерней странице не следует приписывать `aria-current="page"` ссылки архива.

### QA-04 — сценарий фильтра года недоступен

- Статус: **BLOCKED_NOT_IMPLEMENTED**, не регрессия доказанной ранее функции.
- Источник: `src/pages/archive.astro:19–24`.
- Факт: архив выводит статический список трёх выпусков, органов управления фильтрацией нет на обеих ширинах.
- Результат согласованного QA: зафиксировать отсутствие, не добавлять фильтр. Проверить смену года, сброс и пустую выдачу фильтра невозможно.
