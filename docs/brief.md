# «Контур»: бриф проекта

## Результат текущего этапа

Подготовить спецификацию frontend-only сайта вымышленного научного журнала «Контур», без реализации интерфейса.

Критерии приёмки этапа:

- Сохранены `docs/brief.md` и `docs/page-map.md`.
- В карте ровно 10 типов страниц из задания; для каждого указаны URL, цель, блоки, общие компоненты и критерии готовности.
- Зафиксированы локальные данные, поведение поиска, ограничения и общие требования к будущей реализации.
- Код, зависимости и конфигурация не изменены; backend и новые разделы не добавлены.

## Назначение сайта

«Контур» — вымышленный научный журнал. Сайт помогает читателю найти выпуск и статью, ознакомиться с публикацией, а потенциальному автору — узнать требования и способ связи с редакцией.

Основной язык — русский. Тематика журнала, названия материалов и состав редакции будут заданы локальным демонстрационным контентом; отдельный отраслевой функционал не предполагается. Вымышленный характер проекта должен быть явно обозначен, а не выдаваться за действующее издание.

### Основные сценарии

1. Главная → текущий выпуск → статья.
2. Архив → выпуск → статья.
3. Поиск → результаты → статья.
4. О журнале → редакция или контакты.
5. Авторам → требования к рукописи → контакт редакции.
6. Несуществующий адрес → 404 → главная или архив.

## Объём

Включены только: главная, архив, выпуск, статья, поиск, о журнале, редакция, авторам, контакты и 404. Выпуск и статья — повторно используемые шаблоны для нескольких локальных записей, а не дополнительные разделы.

Не входят:

- Backend, API, база данных, CMS, серверные обработчики и серверный поиск.
- Регистрация, авторизация, личные кабинеты и роли пользователей.
- Приём рукописей, загрузка файлов, формы отправки писем, подписка и платежи.
- Комментарии, новости, отдельные страницы авторов, дополнительные разделы и языковые версии.
- Публикация сайта, установка зависимостей и операции записи в Git без отдельного разрешения.

## Технические условия

- Astro со статической сборкой (`output: 'static'`), TypeScript и обычный CSS.
- Все данные и ресурсы локальные; для основного содержимого не требуются внешние сервисы.
- Выпуски и статьи формируются из типизированных локальных записей при сборке. Точные имена модулей и способ хранения выбираются на этапе реализации, без API.
- JavaScript в браузере применяется только там, где необходима интерактивность: поиск и, при необходимости, мобильная навигация.
- Поиск выполняется по локальному индексу статей в браузере. Параметр `q` в `/search/?q=...` хранит запрос; это статическая страница, не серверный маршрут поиска.
- Контакты и инструкция для авторов не имитируют успешную отправку данных. Допустимы обычные ссылки `mailto:` и на локальные файлы, если файлы действительно существуют.

## Локальные данные

| Сущность | Обязательные поля | Необязательные поля |
| --- | --- | --- |
| Журнал | название, краткое описание, отметка об учебном характере, контактный адрес | ISSN, периодичность — только если заданы явно |
| Выпуск | уникальный slug, год, номер, заголовок, дата публикации, упорядоченные ссылки на статьи | обложка, описание, локальный PDF |
| Статья | уникальный slug, ссылка на выпуск, заголовок, авторы, аннотация, ключевые слова, локальный полный текст | DOI, страницы, локальный PDF, библиография |
| Автор в статье | имя | организация |
| Член редакции | имя, роль | организация, краткая справка, фотография |
| Информационная страница | заголовок и структурированный локальный текст | связанные ссылки внутри утверждённой карты |

Ссылки статьи и выпуска должны согласовываться в обе стороны. Порядок статей задаёт выпуск; текущим считается самый новый выпуск по дате публикации. При отсутствии выпусков используется пустое состояние, а не несуществующий «текущий выпуск».

Индекс поиска содержит только необходимые локальные сведения: заголовок, имена авторов, аннотацию, ключевые слова, ссылку на статью и сведения о выпуске. Поиск не требует загрузки полных текстов всех статей.

Необязательные поля скрываются вместе с относящимися к ним подписями и элементами управления. Не создавать вымышленные DOI, недействующие ссылки на скачивание и пустые блоки метаданных.

## Общая структура интерфейса

В текущем репозитории есть только стартовая `src/pages/index.astro`; собственных layouts, дизайн-токенов и общих компонентов пока нет. Ниже — планируемые элементы, а не существующие реализации.

- `BaseLayout`: язык `ru`, метаданные страницы, ссылка пропуска к содержимому, шапка, основной контент и подвал.
- `SiteHeader`, `SiteNav`, `SiteFooter`: единая навигация, название журнала, отметка об учебном проекте. Пункты ведут только в утверждённые разделы.
- `PageHeading`, `Breadcrumbs`: единый заголовок страницы и путь для внутренних страниц; текущий пункт не является ссылкой.
- `IssueCard`, `ArticleCard`, `ArticleMeta`, `PersonCard`: повторяемое представление выпусков, статей, метаданных и редакции.
- `SearchForm`, `EmptyState`: форма локального поиска и понятные пустые состояния.
- `Prose`: единое оформление длинных текстов статей и информационных страниц.
- Общие CSS-токены: цвет, типографика, интервалы, ширина контейнера, границы и состояния фокуса. Конкретная визуальная система определяется при реализации и переиспользуется всеми страницами.

## Общие критерии готовности будущей реализации

Эти требования применяются ко всем страницам вместе с критериями из `page-map.md`.

### Контент и навигация

- Есть уникальный заголовок документа, один основной `h1`, корректная иерархия заголовков и семантические области страницы.
- Все внутренние ссылки ведут на существующие статические страницы; нет заглушек `href="#"`, фиктивных кнопок и обещаний отсутствующих функций.
- Доступны переходы по основным сценариям из брифа. Текущий раздел навигации обозначен не только цветом.
- Тексты читаются без JavaScript; исключение — интерактивная выдача поиска, для которой предусмотрено сообщение `noscript`.

### Адаптивность и доступность

- На ширинах 360 и 1440 CSS-пикселей нет горизонтальной прокрутки страницы, обрезанных заголовков и перекрытия интерактивных элементов.
- Проверены заголовок статьи длиной не менее 180 символов, не менее 8 авторов, длинное название организации и длинная ссылка в тексте.
- Проверены пустые коллекции и отсутствие каждого необязательного поля; нет сломанных изображений, пустых подписей и недействующих ссылок.
- Вся навигация и поиск доступны клавиатурой, виден фокус, поля имеют подписи, изображения — подходящий альтернативный текст. Декоративные изображения имеют пустой `alt`.
- Контраст обычного текста — не ниже 4.5:1; увеличение текста до 200% не скрывает содержимое и действия.

### Проверки

- `npm run check` и `npm run build` завершаются без ошибок.
- После реализации выполнена проверка в браузере на узком и широком экране, включая поиск, пустые состояния и переходы.
- Для dev-сервера соблюдаются команды из `AGENTS.md`: `astro dev --background`, управление через `astro dev status`, `astro dev logs`, `astro dev stop`.
- Проверка 404 учитывает, что HTTP-статус и обработка неизвестных URL зависят от статического хостинга; без выбранного хостинга нельзя заявлять проверенной его настройку.

На текущем документальном этапе сборка и браузерная приёмка интерфейса не требуются: интерфейс ещё не реализован. Далее за итерацию реализуется один шаблон или одна связная группа компонентов, без расширения карты.
