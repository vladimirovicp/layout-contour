# Страница 404: результат этапа

## Результат

Добавлена `src/pages/404.astro` на существующем `BaseLayout`: «Ошибка 404», заголовок «Страница не найдена», короткое объяснение и обычные ссылки на `/`, `/archive/`, `/search/`. Рядом с поиском явно указано, что его логика ещё не подключена.

Шапка, подвал, типографика, фокус и сетка переиспользуются; дизайн-токены и другие исходные файлы не менялись. Клиентских скриптов, кнопки «Назад», зависимостей и настроек хостинга нет. Предыдущие изменения сохранены.

## Проверки

- `npm run check`: 25 файлов, 0 ошибок, предупреждений и подсказок.
- `npm run build`: успешная статическая сборка, 23 страницы; создан `dist/404.html`.
- Chromium / Playwright, production preview: прямое открытие `/404.html` — HTTP 200, правильный заголовок документа, один `h1`, общая навигация и три ссылки выхода.
- На 390 и 1440 CSS-пикселях все ссылки проверены в отдельных новых вкладках: главная, архив и страница поиска отвечают HTTP 200. От истории посещений действия не зависят.
- Горизонтального переполнения нет, в том числе при тексте 200%. Колонка содержимого — 350 / 792 px, высота ссылок — 44 px. Скриншоты просмотрены.
- Клавиатура: ссылка пропуска переводит фокус в `main`; следующая ссылка ведёт на главную, имеет сплошной контур 3 px и открывается по Enter.
- Неизвестный вложенный URL `/missing/deep/path/` в локальном preview показывает эту же страницу с HTTP 404; ссылки остаются корневыми. Сообщение браузерной консоли о статусе 404 этого запроса ожидаемо.
- `git diff --check`: без ошибок пробелов; Git предупреждает о будущей нормализации LF → CRLF в ранее изменённых файлах.
